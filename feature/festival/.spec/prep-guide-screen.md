# 준비 안내 (S15)

Figma S15 1~3단계. `FestivalCoordinator`가 탐색을 소유하고 `FestivalFlow`가 깃발 화면을 구성한다. 일정과 준비물 화면은 AppFlow의 Composable 슬롯으로 전달한다. feature 간 sources 의존은 추가하지 않는다.

## 진입

- 목록에서 받은 적 없는 팩 다운로드가 Updated/NotModified로 끝났고 현재 세션이 있을 때만 준비 안내를 요청한다.
- 다운로드 시작 당시 목록 visit token을 완료 효과에 보존한다. 현재 token·목록 최상위·사용자가 일치할 때만 받고, 서버 일정 조회가 끝난 뒤에도 재확인한다.
- 대상 캐시 문서에 매핑 가능한 일정이 있고 조회가 성공하면 1단계로, 조회 실패나 일정 없음은 저장하지 않고 2단계로 간다.
- 기존 팩 업데이트 및 보드 다운로드는 진입 조건에 포함하지 않는다.

## 단계와 저장

1. 기존 SchedulePick을 쓴다. 대상과 일치하는 보드의 표시 문서를 우선하고 그 외에는 대상 팩 캐시를 읽는다. 저장 성공은 기존 savedSchedules 알림을 한 번 보낸 뒤 2단계로 간다. 건너뛰기는 저장하지 않는다.
2. 기존 FlagViewModel/카드/필터로 대상 축제 깃발을 보여 준다. 존 이름은 대상 캐시에서 읽는다. 카드 본문은 상세를 열지 않고 팔로우만 동작한다. 로그인·약관은 부모 흐름으로 전달한다. 일반 깃발 화면의 ScreenView 이벤트를 추가 발생시키지 않는다.
3. 기존 PackDetailViewModel과 체크리스트 행·추가 행으로 준비물을 저장한다. 완료와 건너뛰기는 준비 경로 전체를 제거한다. D-1 알림 보장 문구는 실제 Android 등록/구독 근거가 없어 표시하지 않는다.

나중에 하기는 모든 준비 경로를 제거하고 뒤로 가기는 이전 단계로 간다. 준비 중에는 탭 바를 숨긴다.

## 진행 중 작업

사용자 next/skip/later/back은 일정 저장·팔로우·체크리스트 저장이 진행되는 동안 막는다. 체크리스트 입력은 계속 허용하며 저장 큐가 비면 이동을 다시 허용한다. prep 팔로우에만 15초 제한을 적용하고 timeout은 기존 실패 토스트로 표시한다. 일반 깃발 경로 제한은 바꾸지 않는다.

계정 변경과 외부 딥링크(다른 탭의 깃발/팩 포함)는 예외로 준비 경로를 제거하고 대기 상태를 초기화한다. 화면 범위 작업은 취소될 수 있다. Android 토스트는 하단이다.
